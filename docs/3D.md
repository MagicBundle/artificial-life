# 3D world: design proposal

Status: proposal, not implemented. Written 2026-10-12. `docs/DESIGN.md` stays the normative spec; each
implementation PR moves the parts it builds into DESIGN.md (new §27) with Review-log rows, as for the director.

## 0. Owner decisions (2026-10-12)

| # | question | decision |
|---|---|---|
| 1 | kind of 3D | **(b) 3D with gravity and a floor.** Periodic in x and y, bounded in z (floor and surface). |
| 2 | code strategy | **(a) `world.dims` config constant.** Default 2; 2D runs, tests and the golden digest stay bit-identical. |
| 3 | 3D viewer | **(b) a Swift viewer in AlifeControl** (Metal; see §8 for why not RealityKit). |
| 4 | timing | **The 2D director evaluation (DIRECTOR.md §9) runs first.** 3D work starts after it. |

Open questions for the owner are collected in §11. The implementing session asks them before the PR that
needs the answer.

## 1. Goals and non-goals

**Goals.**
- Agents live in a water-column-like volume. Life near the floor is cheap; climbing against gravity costs
  energy.
- Food is distributed by depth (a benthic band at the floor and an optional photic band near the surface), so
  vertical niches can form.
- Corpses sink. This sets up a downward nutrient flow ("marine snow").
- Bonded structures can take real 3D shapes. This is the main scientific payoff: the 2D run never sustained
  bodies (RESEARCH.md P2).
- Every existing guarantee carries over:
  - the exact 16-term energy ledger;
  - determinism per backend;
  - replay;
  - the director's safety rules and log.

**Non-goals for v1.** No buoyancy actuator (§11 Q3), no fluid dynamics, no terrain, no 3D bodies with
rotation coupling (bonds stay point-to-point springs), and no 2D↔3D genome transfer.

## 2. Coordinates and boundaries

- `pos` has shape (N,3) as (x, y, z). x and y are periodic on `[0, L)` as now; z lies in `[r, H − r]`, with
  `world.height = H`.
- `ops.min_image` applies to x and y only; dz is the plain difference. `ops.wrap` wraps x and y and clamps z.
  The clamp is the floor and surface contact. Velocity into a boundary is zeroed after the clamp, and a counter
  `Z_CLAMPS` records it.
- **Grounded:** `z ≤ r + floor_eps`. Grounded agents can harvest the benthic band (through the 3D lattice,
  §5). They also get floor friction: grip applies its full drag factor to horizontal motion only when
  grounded. Whether grip also slows sinking off the floor is a tuning item (§9).
- **Gravity:** a constant force `−physics.gravity · ẑ` on every survivor (overdamped, so sinking speed is
  `g/γ`). It must satisfy `gravity < thrust_max` so agents can climb. Hovering then costs
  `move_cost·(g/thrust_max)²` per step through the existing movement cost. There is no new ledger term:
  gravity does no bookkeeping work in an overdamped model.

## 3. Orientation and the brain's frame

- **Representation:** yaw θ (the existing `heading`) plus a new `pitch` φ, clamped to `[−φ_max, φ_max]` with
  `φ_max = 80°`. Gravity defines "up", so roll is unnecessary. Yaw/pitch has no float drift (a quaternion
  needs renormalising) and no gimbal problem inside the clamp.
- **Body frame:**
  - `fwd = (cos φ cos θ, cos φ sin θ, sin φ)`;
  - `lat = (−sin θ, cos θ, 0)`;
  - `up = fwd × lat`.

  `ops.to_body` gains a 3D variant returning (fwd, lat, up) components. The lateral axis stays horizontal,
  which keeps sensing intuitive under gravity.
- **Outputs:** `OUT_TURN` stays yaw; a new `OUT_PITCH` changes φ by up to `turn_max`. The turn cost becomes
  `turn_cost·(|turn| + |pitch|)/turn_max`, a cost change only with no new ledger term.

## 4. Genome layout for dims = 3

`layout.py` becomes a function of `dims`. The dims = 2 values are unchanged, and `GENOME_LAYOUT_VERSION` is
per dims (2D stays 1; 3D starts at 2).

| block | 2D | 3D |
|---|---|---|
| `IN_VEL` | 2 (fwd, lat) | 3 (fwd, lat, up) |
| `IN_RES_GRAD` | 2 | 3 |
| `IN_CHEM_GRAD` | 2·NCH = 6 | 3·NCH = 9 |
| neighbour features NF | 7 (`DX`, `DY`, …) | 8 (+ `DZ`) |
| targeting descriptor F | 6 | 7 |
| bond-slot block `BOND_W` | 5 | 6 (+ `DZ`) |
| new inputs | — | `IN_DEPTH` (z/H), `IN_PITCH` (sin φ), `IN_GROUNDED` |
| D_IN | 69 | 84 |
| new outputs | — | `OUT_PITCH` |
| `OUT_Q_BOND`, `OUT_Q_ATTACK` | F = 6 each | F = 7 each |
| D_OUT | 35 | 38 |

Brain cost grows by about 20% (D_IN·H + H·D_OUT). This is small next to the neighbour search.

## 5. Fields

- **Lattices:** resource is int32 and chemicals are f32, both with shape (FZ, FG, FG), where `FZ = H /
  field_cell` and `FG = L / field_cell`. Index order is [z, y, x].
- **Integer diffusion:** `ops.int_diffuse` gains a third axis with **no-flux boundaries in z** (periodic in x
  and y). It must stay an exact flux stencil, so the total is conserved bit-for-bit; this needs its own test.
  Chemical diffusion uses the same boundary rule in float.
- **Fertility:** `clip(fertility_base + Σ_p w_p · gx_p ⊗ gy_p, 0, 1)` as now, multiplied by a **vertical
  profile** `V(z)`:
  - a benthic band `exp(−z/λ_b)`;
  - plus an optional photic band `a_s · exp(−(H − z)/λ_s)` (§11 Q1).

  Keep it elementwise; no GPU matmul (F20). The (PP, FG, FG) patch term is computed once and broadcast over
  z. Do not materialise (PP, FZ, FG, FG).
- **Corpses sink:** `E + S` is scatter-added into the **floor cell** below the corpse, `(0, cy, cx)`. That
  keeps the same `FLOW_CORPSE` ledger term at a different cell. The scatter lives in `ops.py` (lint rule).
- **Sensing:** the resource and chemical gradients are 3D central differences. The z neighbours at the
  boundaries use one-sided differences, which equals no-flux mirroring.

## 6. Neighbour search and placement

- **Hash grid:** `G_xy × G_xy × G_z` cells, with `G_z = floor(H / R)` and z non-periodic. The search covers
  3×3×3 cells (27C candidates instead of 9C), with out-of-range z layers masked. The brute-force kNN equality
  test gets a 3D variant that covers the floor, the surface and x/y seams.
- **Offspring:** placed at `offspring_distance` in a uniformly random direction on the sphere, then z-clamped.
- **Immigrants:** uniform in x and y; z is uniform in `[r, H − r]`, or at the surface (§11 Q4).
- **Founders:** uniform in the volume with random yaw and pitch. These draws use new init streams (versioned
  RNG); the dims = 2 streams are untouched.

## 7. Everything else

- **Bonds and springs:** 3-vector offsets `(N,B,3)`. The forces are already vector-valued and antisymmetric
  per pair; check that the test still holds in 3D.
- **Director levers:** `patch_shift` moves patches in x and y only. The vertical profile is not a lever in v1.
  The safety rules, budgets, log and replay are unchanged.
- **Metrics (dims = 3 only, new keys):**
  - depth distribution (mean, quartiles, grounded fraction);
  - mean speed (also deferred for 2D in DESIGN §23.2);
  - vertical niche occupancy per clade;
  - body extent in z.
- **Invariants:**
  - z stays in `[r, H − r]`;
  - pitch stays in `[−φ_max, φ_max]`;
  - the lattice shapes are right;
  - the ledger closes;
  - `full_check` gets 3D branches.
- **Config:**
  - `world.dims` (default 2);
  - `world.height`;
  - `physics.gravity`, `physics.floor_eps`;
  - `fields.benthic_lambda`, `fields.photic_amp`, `fields.photic_lambda`.

  All new keys default to off or 2D and go in `config.POST_V01_KEYS`. dims = 3 changes the compiled step and
  the layout, so it is hashed when not default. Resume or fork across dims is refused with a clear error. A new
  preset is `64k3d` (§9).
- **CLI:** `inspect` reports dims, and `bench` works unchanged. The 2D MLX `render` and `view` refuse dims = 3
  with a pointer to the Swift viewer.

## 8. Viewer (Swift, in AlifeControl)

- **Rendering:** raw Metal through `MTKView`, drawing instanced spheres (or impostor billboards) for agents
  and line segments for bonds, with an orbit and fly camera.
  - RealityKit's high-instance-count path (`LowLevelMesh`) needs macOS 15, and the app targets macOS 14.
  - SceneKit is soft-deprecated.
  - Metal handles 64k+ instances at 60 fps on the M5 Pro.
- **Data path:** a new `alife stream RUN|FILE` command re-simulates from a checkpoint, as `view` does. It
  writes length-prefixed binary frames to stdout:
  - a JSON header (dims, L, H, N, colour mode);
  - per frame: alive mask, pos f32, yaw and pitch f16, colour u32, bond pairs.

  The GUI already launches `.venv/bin/alife` as a `Process`, so it reads the pipe. Like `view`, it never
  writes into the run directory.
- **Display options:**
  - colour modes as in 2D (tag, clade, energy, kin);
  - optional translucent floor and surface planes;
  - an optional resource or chemical slice plane at a chosen z;
  - pause, step and speed controls;
  - a snapshot to PNG.
- **Scope:** the viewer also accepts dims = 2 streams (z = 0), so it can later replace pygame for 2D.

## 9. Sizing, performance and tuning

**Starting point: the `64k3d` preset.**
- `L = 320`, `H = 80`: volume 8.2M, which matches the 2D neighbour density for about 33k agents if they spread
  uniformly. Under gravity they will crowd the floor, so retune.
- `field_cell = 4`, giving an 80×80×20 lattice of 128k cells.
- Sensing radius 6, giving a 53×53×13 hash grid.
- `gravity = 0.03`, so net climbing speed is about 0.07 at full thrust.

**Expected cost.**
- The neighbour search is about 3× (27 vs 9 cells).
- Fields are about 2× (128k vs 65k cells, 7-point stencil).
- The brain is about 1.2×.
- Estimate 30–40 steps/s versus 61 in 2D. Measure with `bench --stages` after PR C.

**Tuning risk.** This is the highest-risk part. The 2D defaults were tuned for 2D contact rates and diffusion.
In 3D:
- chemical signals dilute as 1/r rather than logarithmically;
- encounters are rarer at the same density;
- gravity concentrates life on the floor.

The 3D variants of `test_affordances` and the slow ecology test must pass before any long run.

## 10. PR plan

Each PR keeps every 2D test and the 2D golden digest unchanged, and passes `ruff check`, `ruff format --check`
and `pytest -m "not slow"`. DESIGN.md (§27) and the Review log are updated in the same PR as the behaviour.

1. **Dims plumbing.**
   - Add `world.dims` and `world.height`, and turn `layout` into a function of dims.
   - Store dims in checkpoint metadata; refuse cross-dims resume and fork.
   - Validation rejects dims = 3 until PR 3. No behaviour change.
2. **Geometry core.**
   - Yaw/pitch orientation, 3D `to_body`, z-clamped `wrap`, x/y-only `min_image`.
   - 3D hash grid and kNN test.
   - Gravity and floor in `physics`; 3D bond offsets; offspring, immigrant and founder placement.
   - Unit tests with dims = 3 still gated off.
3. **3D fields and enablement.**
   - The (FZ, FG, FG) lattices, no-flux `int_diffuse` with an exact-conservation test, vertical fertility
     profile, sinking corpses, 3D sensing gradients.
   - Ledger-closure tests in 3D; enable dims = 3; pin a 3D golden digest.
4. **Metrics, invariants, director and CLI.**
   - The dims = 3 metrics and `full_check` branches; the director in 3D.
   - `alife stream` with its frame-protocol tests.
5. **Swift viewer.**
   - The Metal view in AlifeControl, plus GUI levers for the new config keys.
   - Build with `cd gui && swift build`.
6. **Ecology and first run.**
   - The `64k3d` preset; 3D `test_affordances` and slow ecology tests; `bench`.
   - A first long run, analysed with `alife activity` and the signal-information tools.

## 11. Open questions for the owner

1. **Vertical food profile.** Floor only (benthic), or floor plus a photic band near the surface? The
   recommendation is both, with the photic band optional, because two food bands separated by a costly water
   column create niches. Needed before PR 3.
2. **Surface boundary.** A solid ceiling (clamp, as at the floor) or the same clamp without grounding. The
   recommendation is the clamp without grounding: the surface is not a floor. Needed before PR 2.
3. **Buoyancy actuator.** None in v1 (thrust only), or a heritable buoyancy trait or output with an energy
   cost. The recommendation is none in v1, then reconsider after the first run.
4. **Immigrant placement.** Uniform in the volume, or dropped at the surface so they must sink to the floor.
   The recommendation is uniform.
